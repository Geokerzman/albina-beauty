# Albina Beauty Concept · Website redesign

Публичный сайт работает на **Next.js 16 App Router, React 19 и TypeScript**. Контент редактируется в **Payload CMS** с админкой на **shadcn/ui**.

## Запуск

```bash
npm install
npm run dev
```

Откройте `http://localhost:3000`.

## Настройка CMS

Для проекта используйте Node.js 24.22.3 или другую версию из `engines.node` в `package.json`.

1. Скопируйте `.env.example` в `.env.local`. Сгенерируйте значение для `PAYLOAD_SECRET` командой `node -e "process.stdout.write(require('node:crypto').randomBytes(32).toString('hex'))"` и запишите его в `.env.local`.
2. Выполните `npm run cms:migrate`, чтобы создать таблицы SQLite.
3. Задайте `CMS_EDITOR_EMAIL` и `CMS_EDITOR_PASSWORD` в окружении терминала. Пароль должен содержать минимум 12 символов. Выполните `npm run cms:create-editor` и удалите пароль из окружения.
4. Запустите или перезапустите `npm run dev` и войдите на `http://localhost:3000/admin/`.

В редакторе выберите блок, измените поля и нажмите **Veröffentlichen**. Поля показывают текущий контент сайта сразу после настройки. Тексты, ссылки, изображения и элементы списков редактируются по отдельности. Для общих блоков, например меню, подвала и формы заявки, правка применяется везде, где блок используется. На публичном сайте изменения видны со следующего запроса.

На сервере используйте HTTPS и постоянный диск для файла `CMS_DATABASE_URL` и каталога `CMS_MEDIA_DIR`. Примените миграции перед первым запуском с включённой CMS и сохраняйте оба пути при обновлениях. Без `PAYLOAD_SECRET` сайт показывает исходное содержимое.

```bash
npm run check:content
npm run typecheck
npm run build
npm start
```

Для проверки production-сборки остановите dev-сервер перед `npm start`. `NEXT_PUBLIC_SITE_URL` задаёт основной адрес для canonical, Open Graph, sitemap и robots; образец в `.env.example`.

## Что реализовано

- 31 публичный маршрут: все 28 исходных адресов, `/karriere/`, `/shop/` и `/termin-vereinbaren/`.
- 13 страниц процедур, категории, каталог с фильтрацией и поиском.
- Единая база 101 ценовой позиции: общий прайс, пакеты, дополнительные зоны лазера и отдельные процедуры из исходных страниц.
- Мобильное меню, десктопное меню категорий, открываемые биографии команды.
- Галерея с полноэкранным просмотром и клавиатурными стрелками.
- Поиск и фильтрация прайса, раскрываемые описания процедур, вопросы и вакансии.
- Форма подготовки запроса: выбранная процедура, имя, желаемая дата и комментарий. Человек сам отправляет подготовленное сообщение в WhatsApp. Нет автоматической отправки или фиктивного подтверждения записи.
- Контакты, встроенная Google Maps с пином салона и ссылкой на маршрут, юридические страницы, 404, metadata, sitemap, robots и BeautySalon JSON-LD.
- Архивы WordPress сохранены по старым адресам, содержат переход на общий прайс и исключены из индексации.
- Магазин представлен страницей персональной продуктовой консультации; корзина, товары и оплата не выдумываются для недоступного исходного магазина.

## Основные файлы

| Файл | Назначение |
|---|---|
| `src/content/site.ts` | Студия, услуги, команда, галерея, вакансии, связи с прайсом |
| `src/content/prices.json` | Исходные значения прайса |
| `src/content/block-copy.json` | Исходные тексты, ссылки и изображения блоков |
| `src/content/pages.ts` | Типизированные блоки и порядок секций главной; список дополнительных маршрутов |
| `src/content/legal.json` | Юридический текст, перенесённый с исходного сайта |
| `src/content/source-copy.json` | Снимок исходных текстов для сверки |
| `src/components/page-sections.tsx` | Шаблоны страниц и рендерер блоков главной |
| `src/components/interactions.tsx` | Каталог, прайс, галерея, команда, FAQ |
| `src/components/booking.tsx` | Диалог и форма подготовки запроса |
| `src/components/ui/` | UI-примитивы с доступными диалогами |
| `src/app/globals.css` | Дизайн-токены, компоненты и адаптивные правила |
| `src/app/(site)/[[...slug]]/page.tsx` | Публичные страницы с контентом из CMS |
| `src/app/admin/` | Редактор сайта на shadcn/ui |
| `src/cms/` | Конфигурация Payload, миграции, поля и чтение блоков |
| `screenshots/redesign/` | QA и скриншоты новой версии |
| `docs/DEVELOPMENT_PLAN.md` | Исходный план развития |
| `docs/CONTENT_DECISIONS.md` | Решения по переносу, спорные цены и проверка перед публикацией |
| `docs/ASSETS.md` | Происхождение фотографий, шрифтов и hero-мотива |

Все 28 старых адресов проверяются скриптом `npm run check:content`. Браузерный обход для локальной QA: `python3 scripts/qa-site.py` (требуется `agent-browser` и запущенный сайт). Эта проверка не отправляет заявки.

Результаты проверок: [docs/VERIFICATION.md](docs/VERIFICATION.md).

Дизайн и код подготовлены в локальном проекте; боевой домен и исходный WordPress не менялись.
